# Automated Report Generator
## Overview
The Automated Report Generator project demonstrates how Python and Pandas can be used to transform structured petroleum production data into a formatted field production status report.
Instead of manually reviewing individual data points and preparing a report, the program automatically generates several sections of a field report, including an executive summary, well-status table, performance rankings, risk flags, recommendations, and a report footer.
The completed report can also be saved automatically as a timestamped text file.
---
## Project Objective
The objective of this project is to build an automated reporting workflow that can:
- Load production data
- Calculate important field-level metrics
- Rank well performance
- Identify wells requiring attention
- Generate recommendations based on predefined data rules
- Produce a structured production report
- Save the report automatically as a text file
This project builds on earlier data-analysis and data-cleaning work by moving from analysis toward automated reporting.

Executive Summary

The program automatically calculates several high-level field metrics.

Using the built-in dataset, the report produces:

* Total field production: 3,558 bbl/day
* Active well production: 3,379 bbl/day
* Active wells: 5 of 7
* Wells under review: 2
* Average water cut: 22.3%
* Field efficiency: approximately 95.0%

The executive summary is designed to provide the most important field-level information at the beginning of the report.

⸻

Well Status Table

The program creates a formatted table containing:

* Well name
* Average production
* Water cut
* Days active
* Well status

The wells are automatically sorted from the highest producer to the lowest producer.

The program also adds a warning indicator when water cut is greater than 35%.

⸻

Performance Rankings

The report automatically identifies:

Top 3 Producers

The built-in dataset ranks:

1. Well_Eta — 891 bbl/day
2. Well_Gamma — 742 bbl/day
3. Well_Epsilon — 634 bbl/day

Bottom 3 Producers

The lowest-producing wells are also automatically identified and displayed in the report.

This allows users to quickly compare high and low performers.

⸻

Risk Flags

The program contains automated rules for identifying wells that may require attention.

High Water Cut

Wells with water cut greater than 35% are flagged.

In the built-in dataset:

* Well_Delta — 45% water cut

Well_Zeta has exactly 35%, so it does not meet the program’s >35% threshold.

Low Production

The program flags active wells producing below 200 bbl/day.

This is a rule defined by the program and should be interpreted as a screening threshold rather than a universal engineering standard.

Wells Under Review

Any well whose status is:

Review needed

is automatically included in the risk section.

⸻

Automated Recommendations

The program generates recommendations based on the detected conditions.

For example, when wells exceed the water-cut threshold, the report generates a water-cut management recommendation.

It also identifies the highest-producing well and recommends reviewing its completion strategy as a possible reference for underperforming wells.

The report also recommends regular production monitoring to help track water-cut trends.

These recommendations are rule-based outputs generated by the program and are not intended to replace detailed engineering or reservoir analysis.

⸻

Automated Report File

After generating the report, the program can save it as a text file.

The filename is automatically generated using the current date and time.

Example:

field_report_20260803_1731.txt

This makes it possible to create multiple reports without manually naming each file.

Current Limitations

This project uses a small sample dataset and rule-based thresholds.

The current implementation also generates a text report rather than a graphical dashboard or PDF report.

The recommendations are based on predefined conditions and should not be treated as standalone engineering decisions.

In a larger real-world implementation, the system would require additional validation, domain-specific rules, data-quality controls, and integration with reliable production databases.
